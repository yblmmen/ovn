Service Mesh Ingress Support

사이드카 없이 eBPF + Daemon 형태의 cilium-envoy(TPROXY)로 동작하는 Cilium Ingress Controller와 shared/dedicated 모드, mkcert TLS Termination을 다룹니다.

Cilium Service Mesh와 Ingress 트래픽 흐름

Cilium Service Mesh는 Istio와 달리 Pod마다 사이드카를 두지 않고, L3/L4는 커널 eBPF로, L7은 노드당 Daemon으로 동작하는 cilium-envoy로 처리합니다.

  1. 클라이언트 트래픽이 cilium-ingress LoadBalancer 서비스로 인입
  2. Cilium eBPF가 감지해 가상의 reserved:ingress IP로 매핑
  3. TPROXY를 통해 cilium-envoy Pod로 리다이렉션 (따라서 일반 tcpdump에서는 중간 논리 과정이 보이지 않음)
  4. Envoy가 Ingress Rule을 검사한 뒤 최종 Backend Pod로 전달 (Client Real IP 보존)
bash
--set ingressController.enabled=true \
--set ingressController.loadbalancerMode=shared \
--set loadBalancer.l7.backend=envoy

Shared vs Dedicated 모드 & Path Type / TLS Termination

  • shared 모드: 여러 Ingress가 단일 cilium-ingress LB IP를 공유합니다.
  • dedicated 모드: Ingress에 ingress.cilium.io/loadbalancer-mode: dedicated 어노테이션을 추가하면 독립 LB 서비스가 생성됩니다.
  • PathType: Exact, Prefix 외에 ImplementationSpecific을 쓰면 Envoy 정규표현식(예: /impl.+) 라우팅이 가능합니다.
  • TLS Termination: mkcert '*.cilium.rocks'로 인증서를 발급해 Secret(demo-cert)으로 등록하고 Ingress spec.tls에 연결하면 HTTPS 종단 처리를 수행합니다.
yaml
apiVersion: "cilium.io/v2"
kind: CiliumClusterwideNetworkPolicy
metadata:
  name: "allow-cidr"
spec:
  endpointSelector:
    matchExpressions:
      - key: reserved:ingress
        operator: Exists
  ingress:
    - fromCIDRSet:
        - cidr: 192.168.10.200/32
