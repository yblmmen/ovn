Service Mesh Ingress Support

사이드카 없이 eBPF + Daemon 형태의 cilium-envoy(TPROXY)로 동작하는 Cilium Ingress Controller와 shared/dedicated 모드, mkcert TLS Termination을 다룹니다.

Cilium Service Mesh와 Ingress 트래픽 흐름

Cilium Service Mesh는 Pod마다 사이드카를 두지 않고 L3/L4는 eBPF로, L7은 노드당 Daemon 형태인 cilium-envoy로 처리합니다.

  1. 클라이언트 트래픽이 cilium-ingress LoadBalancer 서비스로 인입
  2. Cilium eBPF가 감지해 가상의 reserved:ingress IP로 매핑
  3. TPROXY를 통해 cilium-envoy로 리다이렉션 (따라서 일반 tcpdump나 pwru에는 가상 IP 처리 과정이 보이지 않음)
  4. Envoy가 Ingress Rule 검사 후 최종 Backend Pod로 전달 (동일 노드의 Envoy를 활용해 Client Real IP 보존)
bash
--set ingressController.enabled=true \
--set ingressController.loadbalancerMode=shared \
--set loadBalancer.l7.backend=envoy

kubectl exec -it -n kube-system ds/cilium -- cilium ip list | grep ingress
# 172.20.0.173/32   reserved:ingress
# 172.20.1.110/32   reserved:ingress

Shared vs Dedicated, Clusterwide Policy, PathType, mkcert TLS

  • shared vs dedicated: 어노테이션 ingress.cilium.io/loadbalancer-mode: dedicated를 주면 별도 LB 서비스가 분리됩니다.
  • ingress-nginx 공존: 기존 ingressClassName: nginx와 함께 사용할 수 있습니다.
  • CiliumClusterwideNetworkPolicy: reserved:ingress 엔드포인트에 대해 fromCIDRSet으로 인입 IP를 제한할 수 있습니다.
  • PathType: Exact, Prefix, ImplementationSpecific(Envoy 정규표현식 지원)
  • TLS Termination: mkcert '*.cilium.rocks'로 인증서를 발급하고 kubectl create secret tls demo-cert 후 Ingress spec.tls에 연결합니다.
bash
mkcert '*.cilium.rocks'
kubectl create secret tls demo-cert --key=_wildcard.cilium.rocks-key.pem --cert=_wildcard.cilium.rocks.pem
mkcert -install
