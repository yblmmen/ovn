Cilium Native + BGP Control Plane 활용

FRR 라우터와 BGP 피어링을 맺어 PodCIDR, LoadBalancer IP, ClusterIP를 광고하고 externalTrafficPolicy(Cluster vs Local)에 따른 패킷 경로 차이를 검증합니다.

실습 환경 및 Cilium BGP 4대 CRD

라우터 노드에 오픈소스 라우팅 데몬 FRR이 설치되어 있고, Cilium은 routingMode=native, autoDirectNodeRoutes=false, bgpControlPlane.enabled=true로 배포합니다.

  • CiliumBGPClusterConfig: 클러스터 단위로 BGP 데몬과 피어를 맺는 객체
  • CiliumBGPNodeConfigOverride: 특정 노드에만 다른 BGP 설정을 주입
  • CiliumBGPPeerConfig: 타이머, eBGP Multihop, Graceful Restart 등 공통 피어 설정
  • CiliumBGPAdvertisement: PodCIDR, Service LoadBalancerIP/ClusterIP 등 광고 대상 선택

FRR 라우터 및 Cilium BGP 설정

bash
# Router (/etc/frr/frr.conf)
router bgp 65000
 bgp router-id 192.168.10.200
 bgp graceful-restart
 no bgp ebgp-requires-policy
 bgp bestpath as-path multipath-relax
 maximum-paths 4
 network 10.10.1.0/24
 neighbor CILIUM peer-group
 neighbor CILIUM remote-as external
 neighbor 192.168.10.100 peer-group CILIUM
 neighbor 192.168.10.101 peer-group CILIUM
 neighbor 192.168.20.100 peer-group CILIUM
systemctl daemon-reexec && systemctl restart frr
yaml
# kubectl label nodes k8s-ctr k8s-w0 k8s-w1 enable-bgp=true
apiVersion: cilium.io/v2
kind: CiliumBGPAdvertisement
metadata:
  name: bgp-advertisements
  labels:
    advertise: bgp
spec:
  advertisements:
    - advertisementType: "PodCIDR"
---
apiVersion: cilium.io/v2
kind: CiliumBGPPeerConfig
metadata:
  name: cilium-peer
spec:
  timers:
    holdTimeSeconds: 9
    keepAliveTimeSeconds: 3
  ebgpMultihop: 2
  gracefulRestart:
    enabled: true
    restartTimeSeconds: 15
  families:
    - afi: ipv4
      safi: unicast
      advertisements:
        matchLabels:
          advertise: "bgp"
---
apiVersion: cilium.io/v2
kind: CiliumBGPClusterConfig
metadata:
  name: cilium-bgp
spec:
  nodeSelector:
    matchLabels:
      "enable-bgp": "true"
  bgpInstances:
    - name: "instance-65001"
      localASN: 65001
      peers:
        - name: "tor-switch"
          peerASN: 65000
          peerAddress: 192.168.10.200
          peerConfigRef:
            name: "cilium-peer"

Cilium BGP는 Speaker 역할만 하며 수신 경로를 노드 라우팅 테이블에 자동 추가하지 않습니다. 실습 환경에서는 기본 게이트웨이가 eth0이므로 각 노드에 172.20.0.0/16을 라우터로 보내는 경로를 추가해야 양방향 통신이 됩니다. 대규모 클러스터에서는 --set bgpControlPlane.statusReport.enabled=false가 권장됩니다.

bash
ip route add 172.20.0.0/16 via 192.168.10.200
sshpass -p 'vagrant' ssh vagrant@k8s-w1 sudo ip route add 172.20.0.0/16 via 192.168.10.200
sshpass -p 'vagrant' ssh vagrant@k8s-w0 sudo ip route add 172.20.0.0/16 via 192.168.20.200

LoadBalancer IP · ClusterIP 광고 & TrafficPolicy 비교

yaml
apiVersion: cilium.io/v2
kind: CiliumBGPAdvertisement
metadata:
  name: bgp-advertisements-lb-exip-webpod
  labels:
    advertise: bgp
spec:
  advertisements:
    - advertisementType: "Service"
      service:
        addresses:
          - LoadBalancerIP
      selector:
        matchExpressions:
          - { key: app, operator: In, values: [ webpod ] }
bash
kubectl exec -it -n kube-system ds/cilium -- cilium-dbg bgp route-policies
# 65001 tor-switch-ipv4-PodCIDR                     export 192.168.10.200/32 172.20.1.0/24 accept
# 65001 tor-switch-ipv4-Service-webpod-LoadBalancerIP export 192.168.10.200/32 172.16.1.1/32 accept
  • TrafficPolicy = Cluster: 매칭 Pod가 없는 노드(k8s-ctr)도 라우터에 경로가 등록되어, 1차 수신 후 다시 라우터를 거쳐 다른 노드로 가는 불필요한 홉이 발생합니다.
  • TrafficPolicy = Local: 매칭 Pod가 존재하는 노드로만 라우터 경로가 잡히며, eth1으로 들어온 패킷이 바로 해당 노드의 lxc 인터페이스로 전달됩니다.
