Local Redirect Policy (LRP) 공식문서 정리

eBPF를 이용해 특정 IP/포트(AddressMatcher) 또는 ClusterIP 서비스(ServiceMatcher)로 향하는 파드 트래픽을 동일 노드의 로컬 백엔드 파드로 리다이렉션하는 정책입니다.

Local Redirect Policy 개요 및 2가지 매칭 모드

localRedirectPolicies.enabled=true로 활성화하며, 백엔드 파드의 네임스페이스는 정책의 네임스페이스와 일치해야 합니다.

  • AddressMatcher: K8s 서비스에 속하지 않는 IP/Port/Protocol 튜플(예: AWS 메타데이터 169.254.169.254:8080)을 로컬 백엔드 파드로 리다이렉션
  • ServiceMatcher: 기존 ClusterIP 서비스의 eBPF 항목을 LocalRedirect로 대체해 동일 노드의 백엔드로만 트래픽 전달
yaml
# AddressMatcher 예시 (169.254.169.254:8080 -> app=proxy 파드 80포트)
apiVersion: "cilium.io/v2"
kind: CiliumLocalRedirectPolicy
metadata:
  name: "lrp-addr"
spec:
  redirectFrontend:
    addressMatcher:
      ip: "169.254.169.254"
      toPorts:
        - port: "8080"
          protocol: TCP
  redirectBackend:
    localEndpointSelector:
      matchLabels:
        app: proxy
    toPorts:
      - port: "80"
        protocol: TCP
---
# ServiceMatcher 예시
apiVersion: "cilium.io/v2"
kind: CiliumLocalRedirectPolicy
metadata:
  name: "lrp-svc"
spec:
  redirectFrontend:
    serviceMatcher:
      serviceName: my-service
      namespace: default
  redirectBackend:
    localEndpointSelector:
      matchLabels:
        app: proxy
    toPorts:
      - port: "80"
        protocol: TCP

제약사항 및 유즈케이스 (Node Local DNS Cache, EKS kiam)

  • 정책 생성 이전의 기존 활성 연결은 리다이렉션되지 않으므로 필요 시 클라이언트 파드를 재시작해야 합니다.
  • 현재 LRP 정책은 인플레이스 업데이트가 지원되지 않아 변경 시 삭제 후 재생성해야 합니다.
  • EKS kiam 리다이렉션: 파드가 169.254.169.254:80으로 보내는 AWS 메타데이터 요청을 로컬 노드의 kiam-agent(8181 포트)로 가로채 자격 증명을 안전하게 전달할 때 활용합니다.
