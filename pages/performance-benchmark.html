K8s & Cilium 부하 테스트 및 성능 측정

kube-burner와 Prometheus/Grafana로 kube-apiserver 부하 시나리오를 측정하고, APF(PriorityAndFairness) 및 Cilium BPF Map·Conntrack GC 튜닝 방안을 정리합니다.

K8s 1.33 List 스트리밍 개선 및 kube-burner 시나리오

Kubernetes 1.33부터 etcd List 응답을 메모리에 모두 적재하지 않고 한 개씩 구조체로 스트리밍 반환·해제해 OOM 위험이 감소했습니다. kube-prometheus-stack(대시보드 15661, 12006), kube-ops-view, kube-burner를 이용해 단일 배포, 노드 최대 Pod 배포, ConfigMap/Secret 대량 동시 배포 시나리오를 측정합니다.

yaml
# kube-burner 시나리오 핵심 파라미터
jobs:
  - name: create-deployments
    jobType: create
    jobIterations: 100
    qps: 300
    burst: 300

API Flag vs APF & Cilium BPF Map 튜닝

  • API Flag vs APF: --max-request-inflight(400), --max-mutating-requests-inflight(200)는 전체 일괄 제한이지만, FlowSchema + PriorityLevelConfiguration(APF)는 요청별 큐 제어로 유동적입니다.
  • BPF Map 동적 크기: 기본 가용 메모리의 0.25%(ratio: 0.002500). --bpf-map-dynamic-size-ratio=0.01로 늘릴 수 있으나 map flush로 인한 활성 세션 순단에 주의해야 합니다.
  • Conntrack GC 주기: 기본 30초인 --conntrack-gc-interval=10s로 조정해 Map Full을 예방할 수 있습니다.
  • 다중 apiserver: Cilium 1.18부터 --k8s-api-server-urls로 복수의 kube-apiserver를 지정할 수 있습니다.
bash
kubectl exec -it -n kube-system ds/cilium -- cilium status --verbose
# BPF Maps: dynamic sizing: on (ratio: 0.002500)
