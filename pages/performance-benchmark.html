K8s & Cilium 부하 테스트 및 성능 측정

kube-burner와 Prometheus/Grafana로 kube-apiserver 부하 시나리오를 측정하고, APF(PriorityAndFairness) 및 Cilium BPF Map·Conntrack GC 튜닝 방안을 정리합니다.

K8s 1.33 List 스트리밍 개선 및 측정 도구

Kubernetes 1.33에서는 etcd에서 List 응답을 메모리에 모두 올리지 않고 한 개씩 구조체로 만들어 스트리밍 반환·해제하도록 개선되어 OOM 위험이 크게 줄었습니다. kube-prometheus-stack(대시보드 ID 15661, 12006), kube-ops-view, kube-burner를 사용해 3가지 시나리오(단일 배포, 노드 최대 Pod 배포, ConfigMap/Secret 대량 동시 배포)를 측정합니다.

kube-apiserver 부하 제어 (API Flag vs APF)

  • API Flag: --max-request-inflight(기본 400), --max-mutating-requests-inflight(기본 200)는 전체 요청에 일괄 적용됩니다.
  • APF (PriorityAndFairness): FlowSchema와 PriorityLevelConfiguration으로 요청을 분류해 큐별로 유동적 제한이 가능합니다.

Cilium BPF Map 사이즈 & Conntrack GC 튜닝

Cilium은 노드 가용 메모리의 0.25%(ratio: 0.002500)를 BPF Map으로 사용합니다. 대규모 트래픽에서 conntrack map이 가득 차면 신규 Pod/Service 업데이트나 NAT가 실패합니다.

bash
kubectl exec -it -n kube-system ds/cilium -- cilium status --verbose
# BPF Maps: dynamic sizing: on (ratio: 0.002500)
  • 해결책 1 (--bpf-map-dynamic-size-ratio=0.01): Map 크기를 늘리지만 적용 시 map flush가 발생해 기존 활성 세션이 끊어지는 순단에 주의해야 합니다.
  • 해결책 2 (--conntrack-gc-interval=10s): 기본 30초인 Conntrack GC 주기를 단축해 Map Full을 예방합니다(단, 너무 짧으면 CPU 오버헤드 증가).
  • 다중 apiserver 지정: Cilium 1.18부터 --k8s-api-server-urls로 복수의 kube-apiserver 엔드포인트를 지정할 수 있습니다.
