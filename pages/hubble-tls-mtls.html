Hubble API TLS(mTLS) 구성 및 커넥션 디버깅

Hubble Server와 Hubble Relay 간 mTLS 보안 연결을 Helm으로 구성하고, hubble-cli 파드와 openssl s_client로 TLS 핸드셰이크를 검증·디버깅합니다.

Hubble API mTLS 및 Helm 인증서 설정

Hubble Server와 Hubble Relay 간 연결은 기본적으로 mTLS로 보호되며, 두 컴포넌트 모두 인증서 Hot Re-loading을 지원해 기존 연결을 끊지 않고 새 인증서를 적용합니다. Helm 방식은 자동 갱신되지 않으므로 만료 전 helm upgrade로 갱신해야 합니다.

bash
helm upgrade cilium cilium/cilium --namespace kube-system --reuse-values \
  --set hubble.enabled=true \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true \
  --set hubble.tls.auto.enabled=true \
  --set hubble.tls.auto.method=helm \
  --set hubble.tls.auto.certValidityDuration=1095 \
  --set hubble.metrics.tls.enabled=true

kubectl get configmap -n kube-system cilium-config -oyaml | grep hubble-disable-tls
# hubble-disable-tls: "false"면 정상

hubble-cli 파드 & openssl s_client mTLS 검증

공식 hubble-cli.yaml에서 이미지 버전을 quay.io/cilium/hubble:v1.16.4 등으로 맞춰 배포한 뒤, hubble watch peers로 서버 이름(TLS.ServerName)과 IP를 확인합니다.

bash
kubectl exec -it -n kube-system deployment/hubble-cli -- \
  hubble watch peers --server unix:///var/run/cilium/hubble.sock

# 클라이언트 인증서 없이 접속 시: tlsv13 alert certificate required 오류 발생
# 올바른 클라이언트 인증서/키 지정 시 Verification: OK 및 Post-Handshake New Session Ticket 확인
kubectl exec -i -n kube-system deployment/hubble-cli -- \
  openssl s_client -showcerts -servername ${SERVERNAME} -connect ${IP}:4244 \
  -CAfile /var/lib/hubble-relay/tls/hubble-server-ca.crt \
  -cert /var/lib/hubble-relay/tls/client.crt \
  -key /var/lib/hubble-relay/tls/client.key
