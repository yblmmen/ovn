Cilium Security & CiliumNetworkPolicy

Pod Labels 기반 Identity 개념과 CiliumEndpoint(CEP), 그리고 Label·L4 Port·HTTP Path·FQDN(DNS) 기반 CiliumNetworkPolicy 실습 및 실무 적용 고찰을 정리합니다.

Identity & CiliumEndpoint (CEP)

kubectl get cep로 확인하는 id는 Pod별 고유 Endpoint ID이고, identity.id는 Pod Labels 기반의 보안 그룹 ID입니다. CNP가 없으면 기본 All Allow이지만, CNP가 적용되면 기본 정책이 차단(Default Deny)으로 바뀝니다. L3/L4는 cilium-agent, L7은 cilium-envoy가 처리합니다.

4가지 CNP 실습 (Label · L4 Port · L7 Path · FQDN)

yaml
# 1. Label 제어
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: "l3-rule"
spec:
  endpointSelector:
    matchLabels:
      role: backend
  ingress:
    - fromEndpoints:
        - matchLabels:
            role: frontend
---
# 2. L4 Port 제어
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: "l4-rule"
spec:
  endpointSelector:
    matchLabels:
      app: myService
  egress:
    - toPorts:
        - ports:
            - port: "80"
              protocol: TCP
---
# 3. L7 Port + Path 제어 (/public만 허용)
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: "rule1"
spec:
  endpointSelector:
    matchLabels:
      app: service
  ingress:
    - fromEndpoints:
        - matchLabels:
            env: prod
      toPorts:
        - ports:
            - port: "80"
              protocol: TCP
          rules:
            http:
              - method: "GET"
                path: "/public"
---
# 4. FQDN(DNS) 도메인 제어
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: tofqdn-dns-visibility
spec:
  endpointSelector:
    matchLabels:
      app: service
  egress:
    - toEndpoints:
        - matchLabels:
            k8s:io.kubernetes.pod.namespace: kube-system
            k8s:k8s-app: kube-dns
      toPorts:
        - ports:
            - port: "53"
              protocol: ANY
          rules:
            dns:
              - matchPattern: "*"
    - toFQDNs:
        - matchName: cilium.io
        - matchPattern: "*.sub.cilium.io"
실무 회고: NetworkPolicy는 필요한 대상 통신 파악이 어렵고 휴먼 에러 시 장애 영향도가 큽니다. 상황에 따라 Istio Sidecar CRD 등 대안과 운영 가능성을 함께 고려해 적용해야 합니다.
