Hubble을 통한 Cilium Traffic 가시성 확보

Observability(가시성) 확보를 위해 Hubble Relay, Hubble UI, Hubble CLI를 배포하고, CiliumNetworkPolicy(L3/L4 및 L7)와 Flowlog Export(Static/Dynamic)를 실습합니다.

실습 환경 구성

실습 환경은 기존 Vagrant 클러스터와 동일합니다. 다만 초기화 시 kubeadm init/join을 명령어가 아닌 ConfigFile로 구성하며, 초기 배포에서는 hubble.enabled=false로 두고 이후 Helm upgrade로 활성화합니다.

bash
helm upgrade --install cilium cilium/cilium --namespace kube-system \
  --set k8sServiceHost=192.168.10.100 --set k8sServicePort=6443 \
  --set ipam.mode="cluster-pool" --set ipam.operator.clusterPoolIPv4PodCIDRList={"172.20.0.0/16"} --set ipv4NativeRoutingCIDR=172.20.0.0/16 \
  --set routingMode=native --set autoDirectNodeRoutes=true --set endpointRoutes.enabled=true \
  --set kubeProxyReplacement=true --set bpf.masquerade=true --set installNoConntrackIptablesRules=true \
  --set endpointHealthChecking.enabled=false --set healthChecking=false \
  --set hubble.enabled=false --set operator.replicas=1 --set debug.enabled=true

Observability · Hubble 설치

Hubble은 Cilium을 기반으로 eBPF를 활용해 트래픽 가시성을 확보하는 오픈소스입니다. eBPF는 커널 레이어에서 처리되는 것이 많아 기존 방식으로는 가시성 확보가 어려운데, Hubble이 이를 보완합니다.

bash
helm upgrade cilium cilium/cilium --namespace kube-system --reuse-values \
  --set hubble.enabled=true \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true \
  --set hubble.ui.service.type=NodePort \
  --set hubble.ui.service.nodePort=31234 \
  --set hubble.export.static.enabled=true \
  --set hubble.export.static.filePath=/var/run/cilium/hubble/events.log \
  --set prometheus.enabled=true \
  --set operator.prometheus.enabled=true \
  --set hubble.metrics.enableOpenMetrics=true \
  --set hubble.metrics.enabled="{dns,drop,tcp,flow,port-distribution,icmp,httpV2:exemplars=true;labelsContext=source_ip\,source_namespace\,source_workload\,destination_ip\,destination_namespace\,destination_workload\,traffic_direction}"

설치 전/후를 비교하면 Helm Values로 추가한 값이 cilium-config ConfigMap에 반영됩니다. 기본적으로 Hubble API는 각 노드의 cilium-agent 범위에서 동작하지만, hubble-relay를 배포하면 클러스터 전체 범위의 API를 제공합니다. hubble-ui는 내부적으로 nginx를 사용해 NodePort(31234)로 접근하며, src/dst, port, L7 정보 및 클러스터 외부 통신 시 world identity가 표시됩니다.

Hubble Client 설치 및 Port-Forward

Hubble CLI를 설치하고 cilium hubble port-forward로 로컬 4245 포트를 열면 hubble status 및 hubble observe를 사용할 수 있습니다.

bash
HUBBLE_VERSION=$(curl -s https://raw.githubusercontent.com/cilium/hubble/master/stable.txt)
HUBBLE_ARCH=amd64
if [ "$(uname -m)" = "aarch64" ]; then HUBBLE_ARCH=arm64; fi
curl -L --fail --remote-name-all https://github.com/cilium/hubble/releases/download/$HUBBLE_VERSION/hubble-linux-${HUBBLE_ARCH}.tar.gz{,.sha256sum}
sudo tar xzvfC hubble-linux-${HUBBLE_ARCH}.tar.gz /usr/local/bin
which hubble

cilium hubble port-forward&
# ℹ️ Hubble Relay is available at 127.0.0.1:4245

hubble status
# Healthcheck (via localhost:4245): Ok
# Current/Max Flows: 9,801/12,285 (79.78%)
# Flows/s: 31.78
# Connected Nodes: 3/3

ss -tnlp | grep 4245
# LISTEN 0 4096 127.0.0.1:4245 ... users:(("cilium",pid=63667,fd=7))

hubble config view
# config: /root/.config/hubble/config.yaml

Cilium + Hubble 실습 (Star Wars 예제 & CNP)

Cilium 공식 문서 예제(org, class 라벨로 구분된 deathstar, tiefighter, xwing)를 배포합니다. 초기에는 cilium endpoint list의 POLICY가 모두 Disabled 상태이므로 제약 없이 통신됩니다.

bash
k get pods --show-labels
# deathstar-8c4c77fb7-gwzgb   1/1   Running   app.kubernetes.io/name=deathstar,class=deathstar,org=empire
# tiefighter                  1/1   Running   app.kubernetes.io/name=tiefighter,class=tiefighter,org=empire
# xwing                       1/1   Running   app.kubernetes.io/name=xwing,class=xwing,org=alliance

hubble observe -f --from-identity {id}
hubble observe -f --protocol {tcp|udp}
hubble observe -f {pod_name}

CNP 적용 (Not L7 Rule) - Stateful 정책

기존 NetworkPolicy는 A→B를 허용하면 B→A도 허용해야 했지만, CiliumNetworkPolicy(CNP)는 단방향 정책만 허용해도 응답 방향이 자동 허용되는 Stateful 연결 정책을 지원합니다.

yaml
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: "rule1"
spec:
  description: "L3-L4 policy to restrict deathstar access to empire ships only"
  endpointSelector:
    matchLabels:
      org: empire
      class: deathstar
  ingress:
    - fromEndpoints:
        - matchLabels:
            org: empire
      toPorts:
        - ports:
            - port: "80"
              protocol: TCP

적용 후 xwing에서 호출하면 차단되고 tiefighter에서는 허용됩니다. 차단된 트래픽만 필터링하려면 --verdict DROPPED 옵션을 사용합니다.

bash
hubble observe -f --protocol tcp --pod deathstar --verdict DROPPED

CNP 적용 (L7 Rule) & cilium-envoy 흐름

CNP에 rules.http를 추가하면 POST /v1/request-landing처럼 Method와 Path까지 제어할 수 있으며, hubble observe --protocol http에서 HTTP 응답 코드와 latency까지 확인되어 장애 파악에 큰 도움이 됩니다. CNP가 적용되면 정의되지 않은 요청은 Default Deny(Drop) 처리됩니다.

yaml
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: "rule1"
spec:
  description: "L7 policy to restrict access to specific HTTP call"
  endpointSelector:
    matchLabels:
      org: empire
      class: deathstar
  ingress:
    - fromEndpoints:
        - matchLabels:
            org: empire
      toPorts:
        - ports:
            - port: "80"
              protocol: TCP
          rules:
            http:
              - method: "POST"
                path: "/v1/request-landing"

Hubble Flowlog Export (Static vs Dynamic)

로그 시스템이나 SIEM으로 수집하기 위해 hubble.export를 사용할 수 있습니다. static은 cilium-config에 저장되어 rollout이 필요하고 1개만 지정 가능한 반면, dynamic은 별도 ConfigMap(cilium-flowlog-config)으로 재시작 없이 자동 반영되며 다수 설정이 가능해 운영 환경에 적합합니다.

yaml
export:
  fileMaxSizeMb: 10
  fileMaxBackups: 5
  static:
    enabled: false
    filePath: /var/run/cilium/hubble/events.log
    fieldMask: []
    allowList: []
    denyList: []
  dynamic:
    enabled: false
    config:
      configMapName: cilium-flowlog-config
      createConfigMap: true
      content:
        - name: all
          fieldMask: []
          includeFilters: []
          excludeFilters: []
          filePath: "/var/run/cilium/hubble/events.log"
