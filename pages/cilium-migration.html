Calico에서 Cilium으로 무중단 마이그레이션

기존 Calico CNI(192.168.0.0/16, VXLAN 8472) 클러스터에 Dual-Overlay 방식으로 Cilium(10.244.0.0/16, 8473)을 배포하고 CiliumNodeConfig로 노드별 순차 전환을 수행합니다.

Dual Overlay 마이그레이션 원리 및 제약사항

단순히 /etc/cni/net.d 설정만 덮어쓰면 기존 파드는 구 CNI에 남아 통신이 단절됩니다. Cilium은 Dual-Overlay(하이브리드) 모드를 지원해 마이그레이션 중에도 기존 CNI 파드와 Cilium 파드 간 통신을 유지합니다.

  • 필수 요건: 겹치지 않는 새로운 Pod CIDR(예: Calico 192.168.0.0/16 vs Cilium 10.244.0.0/16), cluster-pool IPAM, 충돌하지 않는 오버레이 포트(tunnelPort: 8473).
  • 제약사항: 마이그레이션 중 기존 NetworkPolicy 유지는 미지원이므로 policyEnforcementMode: "never"로 두고 완료 후 복원합니다.

단계별 마이그레이션 절차

yaml
# 1. values-migration.yaml (Secondary Mode로 Cilium 먼저 설치)
operator:
  unmanagedPodWatcher:
    restart: false
tunnelPort: 8473
cni:
  customConf: true
  uninstall: false
ipam:
  mode: "cluster-pool"
  operator:
    clusterPoolIPv4PodCIDRList: ["10.244.0.0/16"]
policyEnforcementMode: "never"
bpf:
  hostLegacyRouting: true
bash
# 2. 노드별 순차 전환 루프 (cordon -> drain -> label -> cilium pod 재시작 -> uncordon)
kubectl cordon $NODE
kubectl drain $NODE --ignore-daemonsets
kubectl label node $NODE --overwrite "io.cilium.migration/cilium-default=true"
kubectl -n kube-system delete pod --field-selector spec.nodeName=$NODE -l k8s-app=cilium
kubectl -n kube-system rollout status ds/cilium -w
kubectl uncordon $NODE

# 3. 모든 노드 전환 완료 후 최종 Helm 값 적용 및 CiliumNodeConfig 정리
cilium install --helm-values values-initial.yaml \
  --helm-set operator.unmanagedPodWatcher.restart=true \
  --helm-set cni.customConf=false \
  --helm-set policyEnforcementMode=default \
  --dry-run-helm-values > values-final.yaml
helm upgrade --install --namespace kube-system cilium cilium/cilium --values values-final.yaml
kubectl -n kube-system rollout restart daemonset cilium && cilium status --wait
kubectl delete -n kube-system ciliumnodeconfig cilium-default
